# Проверка соответствия ТЗ

Проверка исходников: 23 сентября 2026. Реальные результаты запуска — в VALIDATION.md.

| Требование | Состояние |
|---|---|
| Программное управление браузером | Playwright: навигация, формы, клавиши, прокрутка, вкладки, iframe |
| Видимый браузер | По умолчанию; headless включается явно |
| Persistent sessions, ручной вход | Отдельный профиль и режим `--login` |
| Задача текстом в терминале | `--task` или приглашение ввода |
| Claude или OpenAI | Anthropic и OpenRouter; соответствие зависит от выбранной модели, живой прогон ещё нужен |
| Автономные многошаговые решения | Цикл model → tool → observation; качество на реальном сервисе ещё не подтверждено |
| Ограничение контекста | Фрагменты текста/ARIA, пагинация, суммаризация, заметки |
| Как минимум один продвинутый паттерн | Восстановление после ошибок и ограничение повторов |
| Нет готовых сценариев сайтов | В агенте не обнаружены |
| Нет преднаписанных селекторов сервисов | Общие `body` и сбор DOM допустимы; конкретные цели выбирает модель |
| Нет подсказок маршрутов сервисов | Стартовый URL задаёт пользователь, остальные получает модель из страницы |
| Видео и репозиторий | Не созданы в этой проверке; нужны для сдачи |

## Исправлено

- Автозагрузка `.env` с сохранением приоритета окружения.
- Читаемый терминальный вывод, отдельный полный JSONL-журнал.
- Итоговый `blocked`-отчёт при сбое модели.
- Учёт неудачных попыток в ограничителе повторов.
- Возможность честно завершить `blocked`/`partial`, когда наблюдение недоступно.
- Проверка DOM-ревизии и iframe перед действием.
- Сброс наблюдения после ожидания динамического контента.
- Единый размер страниц текста/ARIA и корректный конец пагинации.
- Более аккуратная локальная доска с сохранением задач.
- README с инструкциями Windows, архитектурой и явными ограничениями.

## Что остаётся

Нет доказательства выполнения сложной задачи живой моделью на реальном сервисе. Локальные проверки компонентов не заменяют этот прогон. Security layer с программным подтверждением операций и sub-agent architecture отсутствуют; ТЗ не требует их одновременно с реализованным паттерном восстановления.

## 0.4 — визуальный цикл

Скриншот автоматически добавляется до первого решения и после действий, меняющих страницу; модель анализирует его вместе с текстом/ARIA. Результат на живой vision-модели ещё нужно подтвердить.

## 0.5 — единое наблюдение

Добавлены Context Builder, версия-зависимые ID, заголовок/активная вкладка/прокрутка/viewport, ограниченная сводка различий, эвристический выбор скриншотов, обязательный verify для completed в визуальном режиме. Список ID покрывает до 80 видимых элементов обычного DOM; ARIA и role/selector остаются доступны для остальных целей. Реальный LLM-прогон всё ещё необходим.

## 0.6 — постоянный чат

CLI принимает последовательные задачи/вопросы, сохраняет историю между ходами, поддерживает /retry, /reload, /new, /status, /exit. Ошибки API показывают сообщение сервиса и не закрывают чат. Живое подключение OpenRouter и причину текущего 404 нужно повторно проверить у пользователя.
