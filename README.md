# Browser Agent

**Задача обычным текстом → действия в браузере → проверка результата**

**Python 3.11+ · Playwright · OpenRouter · Chromium**  
**Версия:** 0.9.1 · **Статус:** рабочий прототип

Browser Agent — автономный браузерный агент, который получает задачу на обычном языке, анализирует текущую страницу и самостоятельно выбирает необходимые действия.

Агент умеет переходить по страницам, читать содержимое, заполнять формы, нажимать кнопки и проверять результат выполнения задачи.

Браузер работает в видимом режиме, поэтому за действиями агента можно наблюдать в реальном времени.

Логика не привязана к конкретному сайту: решение о следующем действии принимает подключённая AI-модель, а взаимодействие с браузером, контроль состояния страницы и выполнение команд обеспечивает Python-приложение.

# Возможности

### Навигация

- открытие сайтов;
- переход по ссылкам;
- работа с несколькими вкладками;
- работа с `iframe`;
- прокрутка страниц.

### Взаимодействие со страницей

- ввод текста;
- клики по элементам;
- отправка клавиш;
- выбор значений в `select`;
- переключение checkbox;
- работа с интерактивными элементами интерфейса.

### Анализ страницы

Агент может использовать:

- текст страницы;
- DOM;
- accessibility tree;
- локальный контекст элементов;
- скриншоты — если выбранная модель поддерживает `image input`.

### Сессии

Browser Agent поддерживает сохранение авторизации в отдельном профиле Chromium.

Это позволяет один раз вручную войти в аккаунт, а затем использовать сохранённую сессию при следующих запусках.

### Диалог

В терминале можно:

- отправлять новые задачи;
- задавать уточнения;
- продолжать предыдущую задачу;
- повторять выполнение после ошибки;
- смотреть состояние текущей сессии.

### Проверка результата

Перед завершением браузерной задачи агент должен проверить фактическое состояние страницы и указать свидетельства выполнения.

После работы сохраняются:

- итоговый JSON-отчёт;
- журнал действий;
- ошибки;
- вызовы инструментов;
- информация об использовании модели.

# Быстрый старт

## Требования

Необходимы:

- Python 3.11+;
- интернет;
- Chromium;
- API-ключ OpenRouter;
- модель с поддержкой `tool calling`.

Для режима Vision модель также должна поддерживать изображения.

Использование API зависит от квот, ограничений и стоимости выбранной модели.

---

## 1. Получите проект

```bash
git clone https://github.com/soornyak/-.git browser-agent
cd browser-agent
```

Также можно скачать ZIP-архив репозитория и распаковать его в постоянную папку.

В PyCharm необходимо открыть папку, содержащую:

```text
agent/
requirements.txt
```

Не запускайте проект непосредственно из временной папки WinRAR.

Все дальнейшие команды выполняются из корня проекта.

---

## 2. Установите зависимости

### Windows / PowerShell

Создайте виртуальное окружение:

```powershell
py -m venv .venv
```

Установите зависимости:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Установите Chromium для Playwright:

```powershell
.\.venv\Scripts\python.exe -m playwright install chromium
```

Если рабочая `.venv` уже существует, повторно создавать её не нужно.

Во всех примерах используется Python непосредственно из `.venv`, поэтому отдельная активация окружения не требуется.

---

## 3. Настройте OpenRouter

Запустите мастер настройки:

```powershell
.\.venv\Scripts\python.exe -m agent.cli --setup
```

Мастер запросит:

- API-ключ;
- использование Vision;
- модель.

API-ключ вводится скрыто.

Можно выбрать модель из предложенного списка или нажать `Enter`, чтобы использовать:

```text
openrouter/free
```

Настройки сохраняются в:

```text
.env
```

> Бесплатный маршрутизатор OpenRouter может иметь ограничения по квотам и доступности моделей.

Платные модели автоматически не выбираются. Если модель указывается вручную, её стоимость и доступность необходимо проверить отдельно.

---

## 4. Проверьте подключение

```powershell
.\.venv\Scripts\python.exe -m agent.cli --check
```

Проверка выполняет до двух запросов к модели и может расходовать API-квоту.

Она проверяет:

- доступность модели;
- поддержку инструментов;
- передачу результатов инструментов;
- изображения при включённом Vision.

После успешной проверки можно запускать агента.

```powershell
.\.venv\Scripts\python.exe -m agent.cli
```

После появления:

```text
Вы ›
```

можно отправить задачу, например:

```text
Открой https://example.com и скажи заголовок страницы.
```

# Проверка на демо

В репозитории находится локальная тестовая доска задач.

Она позволяет проверить работу агента без использования внешнего сайта.

## Терминал №1

Запустите локальный сервер:

```powershell
.\.venv\Scripts\python.exe -m http.server 8765 --bind 127.0.0.1 --directory demo
```

Оставьте этот терминал работающим.

---

## Терминал №2

Запустите Browser Agent:

```powershell
.\.venv\Scripts\python.exe -m agent.cli --url http://127.0.0.1:8765
```

После появления:

```text
Вы ›
```

отправьте:

```text
Проверь текущие задачи. Добавь только отсутствующие: подготовить отчёт, проверить договор, отправить результат. Отметь подготовку отчёта выполненной. Проверь, что всего три задачи и одна завершена.
```

Ожидаемый результат:

```text
3 задачи · 2 в работе · 1 завершена
```

После завершения сравните отчёт агента с фактическим состоянием страницы.

Если на доске уже находятся посторонние задачи, агент не должен автоматически удалять их: исходная команда такого разрешения не содержит.

# Вход в аккаунты

Для ручной авторизации без обращения к AI-модели используется режим:

```powershell
.\.venv\Scripts\python.exe -m agent.cli --login --url https://mail.yandex.ru
```

В открывшемся Chromium:

1. войдите в аккаунт;
2. при необходимости пройдите подтверждение;
3. дождитесь полной загрузки сайта;
4. нажмите `Enter` в терминале.

Следующий запуск сможет использовать сохранённую сессию:

```powershell
.\.venv\Scripts\python.exe -m agent.cli --url https://mail.yandex.ru
```

По умолчанию профиль Chromium хранится в:

```text
.profile/
```

Путь рассчитывается относительно папки запуска.

Для постоянного расположения профиля можно использовать:

```text
--profile PATH
```

Один профиль не следует одновременно использовать несколькими экземплярами агента.

Сайт также может самостоятельно завершить сессию и потребовать повторную авторизацию.

Пароли рекомендуется вводить вручную непосредственно в браузере.

> Пример с Яндекс Почтой демонстрирует механизм сохранения браузерной сессии и не означает подтверждённую интеграцию Browser Agent с этим сервисом.

# Команды и настройки

## Команды чата

Команды вводятся после:

```text
Вы ›
```

а не в PowerShell.

| Команда | Действие |
|---|---|
| `/help` | Показать доступные команды |
| `/status` | Показать модель, текущую страницу и состояние сессии |
| `/check` | Проверить API и модель |
| `/reload` | Перечитать `.env`, сохранив браузер |
| `/retry` | Продолжить предыдущую задачу с учётом уже выполненных действий |
| `/new` | Очистить память диалога, сохранив браузерную сессию |
| `/exit` | Закрыть Browser Agent |

`Ctrl+C` останавливает текущую работу и завершает процесс.

История диалога после перезапуска программы не восстанавливается.

При смене модели через `/reload` история также очищается для предотвращения конфликтов между форматами API.

# Настройка `.env`

Пример:

```env
AGENT_PROVIDER=openrouter
OPENROUTER_API_KEY=your-key
AGENT_MODEL=openrouter/free
OPENROUTER_BASE_URL=https://openrouter.ai/api/v1

AGENT_VISION=true
AGENT_MAX_TOKENS=4096
AGENT_TIMEOUT=90
```

### Основные параметры

`AGENT_PROVIDER`

Имя используемого API-провайдера.

Это не URL.

---

`AGENT_VISION=false`

Отключает автоматическую передачу скриншотов модели.

Агент продолжает работать с текстом, DOM и другими доступными представлениями страницы.

---

`AGENT_MAX_TOKENS`

Максимальный размер ответа модели.

Допустимый диапазон:

```text
256–32768
```

---

`AGENT_TIMEOUT`

Таймаут одного HTTP-запроса к модели.

Допустимый диапазон:

```text
5–300 секунд
```

Это не ограничение времени выполнения всей браузерной задачи.

---

Файл `.env` загружается из корня проекта и имеет приоритет над одноимёнными переменными окружения.

После изменения `.env` используйте:

```text
/reload
```

После изменения Python-кода необходимо перезапустить приложение.

# Отчёты

После выполнения задачи Browser Agent выводит путь к сохранённым результатам.

Структура:

```text
runs/
└── <session>/
    ├── task-001/
    │   ├── result.json
    │   └── events.jsonl
    ├── task-002/
    └── ...
```

### `result.json`

Содержит:

- статус задачи;
- итоговый ответ;
- свидетельства выполнения;
- информацию об использовании токенов.

### `events.jsonl`

Содержит:

- шаги агента;
- обращения к инструментам;
- результаты действий;
- ошибки;
- диагностические события.

Следующие задачи получают номера:

```text
task-002
task-003
task-004
...
```

Бинарные скриншоты непосредственно в JSON-журнал не записываются.

---

## Статусы выполнения

| Статус | Значение |
|---|---|
| `completed` | Агент сообщил о завершении после проверки результата |
| `answered` | Агент ответил пользователю без выполнения браузерной задачи |
| `partial` | Задача выполнена только частично |
| `blocked` | Ошибка или ограничение не позволили продолжить |

`completed` означает, что агент выполнил собственную проверку результата.

Это не является независимым внешним доказательством корректности операции.

# Архитектура

Основной цикл:

```text
Наблюдение
    ↓
Решение модели
    ↓
Инструмент
    ↓
Playwright
    ↓
Изменённая страница
    ↓
Новое наблюдение
```

Перед завершением браузерной задачи агент должен вызвать проверку результата и указать свидетельства выполнения.

AI-модель не управляет Playwright напрямую.

Она работает через ограниченный набор инструментов, например:

```text
click_element
type_text
```

Исполнитель отвечает за:

- выполнение действий;
- контроль состояния страницы;
- проверку версии наблюдения;
- обнаружение изменений;
- передачу результата обратно модели.

Проверка цели учитывает:

- конкретный DOM-узел;
- состояние элемента;
- его локальный контекст.

Поэтому изменение несвязанного элемента страницы не обязательно блокирует действие.

Для ограничения размера контекста хранится максимум один актуальный скриншот, а длинная история диалога может сворачиваться в краткое описание.

После пяти последовательных ошибок без успешного действия выполнение останавливается.

# Проверки и ограничения

Для версии **0.9.1** успешно выполняется:

```text
61 автоматический тест
```

В набор входят проверки с реальным Chromium.

Интеграционный тест:

1. открывает локальную доску;
2. создаёт три задачи;
3. завершает одну из них;
4. проверяет итоговое состояние страницы.

Во время теста отдельный счётчик страницы обновляется каждые `10 мс`, что дополнительно проверяет устойчивость механизма контроля DOM.

В автоматическом интеграционном тесте ответы модели задаются программно.

Также выполнялся пользовательский прогон через OpenRouter: агент завершил сценарий и подтвердил наличие трёх задач, одна из которых отмечена выполненной.

Работа с реальной почтой в версии 0.9.1 отдельно не подтверждена.

## Ограничения

Browser Agent остаётся прототипом.

### Надёжность зависит от нескольких компонентов

Результат зависит от:

- выбранной модели;
- структуры сайта;
- API-провайдера;
- доступности модели;
- состояния сети;
- логики Browser Agent.

Бесплатные API-маршруты могут ограничивать запросы даже между успешно выполненными действиями.

### Сложные интерфейсы

Не гарантируется корректная работа со всеми:

- SPA;
- canvas-интерфейсами;
- нестандартными web-компонентами;
- сильно динамическими страницами.

Координатные клики в текущей версии отсутствуют.

### DOM и изображение страницы

DOM и скриншот создаются не абсолютно одновременно.

В редких случаях страница может измениться между двумя наблюдениями.

### Авторизация

Пользователь самостоятельно проходит:

- CAPTCHA;
- 2FA;
- ввод пароля;
- другие проверки личности.

### Проверка результата

Статус:

```text
completed
```

означает, что агент сам проверил результат доступными средствами.

Для критически важных действий результат рекомендуется дополнительно проверять вручную.

# Решение проблем

| Ошибка | Решение |
|---|---|
| `No module named playwright` | Установите `requirements.txt` через Python из `.venv` |
| `requirements.txt` не найден | Перейдите в корень проекта |
| Chromium не установлен | Выполните `python -m playwright install chromium` |
| `ERR_CONNECTION_REFUSED` на `8765` | Запустите локальный demo-сервер |
| Не задан API-ключ | Выполните `--setup` |
| Модель не работает | Выполните `--check` |
| HTTP 400 | Проверьте `Detail` и `error_type` |
| HTTP 401 / 403 | Проверьте API-ключ и права доступа |
| HTTP 402 | Проверьте баланс и spending limit |
| HTTP 404 | Проверьте точный ID модели |
| HTTP 429 | Превышены квоты или rate limit |
| `Stale DOM` | Элемент или его контекст изменились между наблюдением и действием |

---

## HTTP 400

Сам код `400` не определяет точную причину ошибки.

Проверьте:

```text
Detail
error_type
```

Возможные причины:

- неподдерживаемый параметр;
- несовместимый формат истории;
- неподдерживаемое изображение;
- особенности конкретной модели.

---

## HTTP 429

Ошибка означает ограничение API по количеству запросов или квоте.

Частое использование:

```text
/retry
```

не восстанавливает исчерпанную квоту.

---

## После ошибки

Перед повторным запуском проверьте фактическое состояние страницы.

Некоторые действия могли выполниться до возникновения ошибки.

Команда:

```text
/retry
```

просит модель учесть уже выполненные действия, однако полностью исключить повторное выполнение операции невозможно.

# Обновление проекта

Перед обновлением остановите Browser Agent.

Если обновление выполняется заменой файлов, сохраните:

```text
.env
.venv/
.profile/
```

Затем обновите папку:

```text
agent/
```

Команда:

```text
/reload
```

перечитывает настройки `.env`, но не перезагружает изменённый Python-код.

Для изменений кода требуется перезапуск приложения.

# Приватность и публикация

Browser Agent может передавать выбранному AI API:

- текст страниц;
- DOM-контекст;
- скриншоты;
- данные, необходимые для выполнения пользовательской задачи.

Поэтому необходимо учитывать политику конфиденциальности выбранного API-провайдера.

Локальные журналы также могут содержать:

- текст страниц;
- содержимое форм;
- адреса сайтов;
- результаты действий;
- личные данные.

## Не публикуйте

```text
.env
.profile/
.venv/
runs/
```

### `.env`

Может содержать API-ключи.

Для репозитория используйте:

```text
.env.example
```

только с фиктивными значениями.

### `.profile/`

Содержит браузерный профиль, включая cookies и активные сессии аккаунтов.

### `.venv/`

Локальное Python-окружение не должно попадать в Git.

### `runs/`

Перед публикацией журналов обязательно проверьте их содержимое.

## Перед `git push`

Проверьте:

```bash
git status
```

и:

```bash
git diff --cached --name-only
```

Убедитесь, что секреты и локальные данные не попали в commit.

Важно: добавление файла в `.gitignore` не удаляет его из Git, если он уже отслеживается.

Если API-ключ случайно был опубликован, его необходимо **отозвать и создать новый**.

Удаление ключа только из последнего коммита недостаточно.

Пароли рекомендуется вводить вручную непосредственно в браузере.

Ограничения, написанные в системном промпте модели, не являются полноценной технической системой разрешений для критических операций.
