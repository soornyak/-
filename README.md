# Browser Agent

> Автономный AI-агент для управления браузером через обычные текстовые команды.

**Python 3.11+ · Playwright · OpenRouter · Chromium**

Browser Agent получает задачу обычным текстом, анализирует текущую страницу и самостоятельно выбирает необходимые действия: переходит по страницам, читает содержимое, заполняет формы, нажимает кнопки и проверяет результат.

Браузер работает в видимом режиме, поэтому за действиями агента можно наблюдать в реальном времени.

## Возможности

Browser Agent умеет:

* открывать сайты и переходить между страницами;
* анализировать DOM, текст и accessibility tree;
* находить элементы по роли, названию и контексту;
* заполнять формы;
* нажимать кнопки;
* работать с checkbox, select и другими элементами;
* переключаться между вкладками;
* работать с iframe;
* использовать скриншоты для vision-моделей;
* сохранять браузерную сессию;
* работать с авторизованными аккаунтами;
* продолжать задачу после ошибки;
* проверять результат выполненного действия;
* сохранять JSON-отчёты и журнал выполнения;
* записывать видео браузерной сессии.

Главная особенность проекта — логика не привязана к конкретному сайту.

Агент работает по циклу:

```text
Пользователь
    ↓
AI-модель
    ↓
Выбор инструмента
    ↓
Playwright
    ↓
Изменённая страница
    ↓
Новое наблюдение
    ↓
AI-модель
    ↓
Проверка результата
```

## 2. Создание виртуального окружения

### Windows

```powershell
py -m venv .venv
```

Установка зависимостей:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Установка Chromium:

```powershell
.\.venv\Scripts\python.exe -m playwright install chromium
```

---

## 3. Настройка API

Запустите встроенный мастер:

```powershell
.\.venv\Scripts\python.exe -m agent.cli --setup
```

Мастер попросит:

1. API-ключ OpenRouter;
2. настройку Vision;
3. модель для работы агента.

По умолчанию можно использовать:

```text
openrouter/free
```

Настройки сохраняются в:

```text
.env
```

Пример:

```dotenv
AGENT_PROVIDER=openrouter
OPENROUTER_API_KEY=your-key
AGENT_MODEL=openrouter/free
OPENROUTER_BASE_URL=https://openrouter.ai/api/v1
AGENT_VISION=true
AGENT_MAX_TOKENS=4096
AGENT_TIMEOUT=90
```

> `.env` содержит секретный API-ключ и не должен попадать в Git.

# Пример работы

Пользователь пишет:

```text
Открой страницу, найди форму обратной связи, заполни имя и сообщение и проверь, что данные введены правильно.
```

Агент:

```text
1. анализирует страницу;
2. находит необходимые элементы;
3. выбирает подходящий инструмент;
4. вводит данные;
5. получает новое состояние страницы;
6. проверяет результат;
7. возвращает отчёт пользователю.
```

# Локальное демо

В проект входит небольшой тестовый сайт с задачами.

## Терминал №1

Запустите сайт:

```powershell
.\.venv\Scripts\python.exe -m http.server 8765 --bind 127.0.0.1 --directory demo
```

## Терминал №2

Запустите агента:

```powershell
.\.venv\Scripts\python.exe -m agent.cli --url http://127.0.0.1:8765 --record
```

После появления:

```text
Вы ›
```

отправьте:

```text
Проверь текущие задачи. Добавь только отсутствующие: подготовить отчёт, проверить договор, отправить результат. Отметь подготовку отчёта выполненной. Проверь, что всего три задачи и одна завершена.
```

Ожидаемый результат:

```text
3 задачи
2 в работе
1 завершена
```

# Работа с авторизацией

Для сайтов, требующих входа в аккаунт, предусмотрен ручной login-режим.

Например:

```powershell
.\.venv\Scripts\python.exe -m agent.cli --login --url https://mail.yandex.ru
```

Откроется Chromium.

Войдите в аккаунт самостоятельно.

После входа нажмите `Enter` в терминале.

Сессия сохранится в браузерном профиле.

После этого можно запускать:

```powershell
.\.venv\Scripts\python.exe -m agent.cli --url https://mail.yandex.ru
```

без повторной авторизации, пока сама сессия остаётся действительной.

> Пароли, cookies и содержимое `.profile` нельзя публиковать в Git.

# Как работает агент

В упрощённом виде:

```text
User Task
   ↓
Observe
   ↓
LLM
   ↓
Tool Call
   ↓
Playwright
   ↓
Browser
   ↓
Observe
   ↓
LLM
   ↓
Verify
   ↓
Result
```

Модель получает состояние страницы и самостоятельно принимает решение о следующем действии.

После действия агент заново анализирует страницу.

Перед завершением браузерной задачи агент должен выполнить проверку результата.

# Работа с Vision

Если:

```dotenv
AGENT_VISION=true
```

агент может отправлять модели скриншоты текущей страницы.

Для этого выбранная модель должна поддерживать изображения.

Если модель работает только с текстом:

```dotenv
AGENT_VISION=false
```

или:

```powershell
.\.venv\Scripts\python.exe -m agent.cli --no-vision
```

# Отчёты

После выполнения задачи агент может сохранять:

```text
runs/
└── session/
    ├── task-001/
    │   ├── result.json
    │   └── events.jsonl
    │
    └── video/
```

### `result.json`

Содержит:

* статус задачи;
* итоговый ответ;
* подтверждения результата;
* статистику выполнения;
* информацию об использовании модели.

### `events.jsonl`

Содержит журнал работы агента:

```text
наблюдение
→ решение модели
→ инструмент
→ результат
→ новое наблюдение
```

| Статус      | Значение                                            |
| ----------- | --------------------------------------------------- |
| `completed` | Задача выполнена и проверена                        |

# Ограничения

Browser Agent является рабочим прототипом, а не production-RPA системой.

Следует учитывать:

* качество действий напрямую зависит от выбранной модели;
* бесплатные модели могут иметь ограничения и нестабильную доступность;
* сложные SPA могут анализироваться хуже обычных страниц;
* canvas-интерфейсы поддерживаются ограниченно;
* координатные клики не используются;
* CAPTCHA пользователь проходит самостоятельно;
* 2FA пользователь проходит самостоятельно;
* браузерное состояние может измениться между наблюдением и действием;
* успешный статус агента не заменяет ручную проверку критических операций.

# Безопасность

Не публикуйте:

```text
.env
.profile/
.venv/
runs/
```

`.env` может содержать API-ключ.

`.profile` может содержать:

```text
cookies
сессии
токены авторизации
данные аккаунтов
```

`runs/` может содержать:

```text
логи
введённый текст
данные страниц
видео браузера
```

Перед публикацией репозитория всегда проверяйте:

```bash
git status
```

и убедитесь, что секретные данные не попали в коммит.

# Troubleshooting

### `No module named playwright`

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

---

### Chromium не установлен

```powershell
.\.venv\Scripts\python.exe -m playwright install chromium
```

---

### HTTP 401 / 403

Проверьте API-ключ и права аккаунта.

---

### HTTP 402

Проверьте баланс API.

---

### HTTP 404

Проверьте ID модели.

---

### HTTP 429

Провайдер ограничил количество запросов или закончилась доступная квота.

Повторные запросы не устраняют отсутствие квоты.

---

### `ERR_CONNECTION_REFUSED`

Если используется локальное демо:

```powershell
.\.venv\Scripts\python.exe -m http.server 8765 --bind 127.0.0.1 --directory demo
```

Сервер должен оставаться запущенным.
