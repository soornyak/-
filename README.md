Browser Agent
Задача обычным текстом → действия в браузере → проверка результата.

Python 3.11+ · Playwright · OpenRouter · Chromium
Версия: 0.9.1 · Статус: рабочий прототип
Browser Agent получает задачу, анализирует текущую страницу и выбирает действия: переходит по ссылкам, читает содержимое, заполняет поля и нажимает кнопки. Браузер остаётся видимым — за выполнением можно наблюдать.
Логика агента не привязана к конкретному сайту. Решения принимает подключённая модель, а исполнение, наблюдение и проверки выполняет Python-приложение.

Возможности
- Навигация: сайты, вкладки, iframe и прокрутка.
- Действия: ввод текста, клики, клавиши, выбор значений и переключение чекбоксов.
- Наблюдение: текст, DOM, дерево доступности и скриншоты для моделей с поддержкой изображений.
- Сессии: сохранение авторизации в отдельном браузерном профиле.
- Диалог: уточнения, продолжение задач и обработка ошибок в терминале.
- Результаты: проверка состояния, JSON-отчёты, журнал шагов и опциональная видеозапись.
Быстрый старт
Нужны Python 3.11+, интернет и ключ OpenRouter. Модель должна поддерживать tool calling, а для скриншотов — также image input. Использование API зависит от квот и стоимости выбранной модели.
1. Получите проект
git clone https://github.com/soornyak/-.git browser-agent
cd browser-agent
Можно скачать архив и распаковать его в постоянную папку. В PyCharm откройте папку, содержащую agent и requirements.txt.
Не запускайте проект из временной папки WinRAR. Все команды ниже выполняются из корня распакованного проекта.

2. Установите зависимости — Windows / PowerShell
В терминале PyCharm выполняйте команды по очереди:
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m playwright install chromium
Если рабочая .venv уже существует, пропустите первую команду. Не пересоздавайте активное окружение.
В примерах явно указан Python из .venv, поэтому отдельная активация окружения не требуется.
3. Настройте OpenRouter
.\.venv\Scripts\python.exe -m agent.cli --setup
Мастер запросит API-ключ, режим скриншотов и модель. Ключ вводится скрыто. Выберите модель из списка или нажмите Enter для openrouter/free. Настройки сохранятся в .env.
Бесплатный маршрутизатор не отменяет квоты и не гарантирует постоянную доступность. Платная модель автоматически не выбирается; стоимость ручного ID проверяйте отдельно.
4. Проверьте подключение и запустите агента
.\.venv\Scripts\python.exe -m agent.cli --check
Проверка выполняет до двух обращений к модели и расходует квоту: проверяет инструменты, передачу их результатов и изображения при включённом Vision.
После успешной проверки:
.\.venv\Scripts\python.exe -m agent.cli
Дождитесь Вы › и введите, например:
Открой https://example.com и скажи заголовок страницы.
Чтобы открыть сайт при запуске:
.\.venv\Scripts\python.exe -m agent.cli --url https://example.com
При следующих запусках повторять установку и настройку не нужно. Следующее сообщение вводится после ответа агента; параллельный ввод во время выполнения не реализован.

Проверка на демо
В проект входит локальная доска задач.
Терминал №1 — запустите сайт и оставьте его работающим:
.\.venv\Scripts\python.exe -m http.server 8765 --bind 127.0.0.1 --directory demo
Терминал №2 — из той же папки запустите агента:
.\.venv\Scripts\python.exe -m agent.cli --url http://127.0.0.1:8765 --record
После Вы › отправьте одной строкой:
Проверь текущие задачи. Добавь только отсутствующие: подготовить отчёт, проверить договор, отправить результат. Отметь подготовку отчёта выполненной. Проверь, что всего три задачи и одна завершена.
Ожидаемый результат: 3 задачи · 2 в работе · 1 завершена. Сверьте отчёт с реальной страницей. Если на доске есть посторонние задачи, сначала решите, что с ними делать: запрос не разрешает молча удалять их.
Вход в аккаунты
Для ручной авторизации без обращения к модели:
.\.venv\Scripts\python.exe -m agent.cli --login --url https://mail.yandex.ru
Войдите в открывшемся браузере, пройдите подтверждение и дождитесь загрузки аккаунта. Затем нажмите Enter в терминале.
Следующий запуск использует сохранённую сессию:
.\.venv\Scripts\python.exe -m agent.cli --url https://mail.yandex.ru
По умолчанию профиль хранится в .profile относительно папки запуска. Запускайте из той же папки или укажите постоянный путь через --profile. Сервис может завершить сессию и потребовать повторный вход. Два экземпляра агента не должны одновременно использовать один профиль.
Пароль вводите самостоятельно в браузере. Пример с почтой показывает способ авторизации, а не подтверждённую интеграцию с этим сервисом.

Команды чата
Вводятся после Вы ›, а не в PowerShell.
Команда	Действие
/help	Подсказка по командам
/status	Модель, текущая страница и число задач в сессии
/check	Проверка API с расходом квоты
/reload	Перечитать .env, сохранив браузер
/retry	Продолжить последнюю задачу с проверкой уже выполненного
/new	Очистить память диалога, сохранив страницу и вход
/exit	Закрыть сессию и завершить запись видео


Ctrl+C останавливает текущую работу и завершает процесс. История диалога не восстанавливается после перезапуска. При смене модели через /reload она также очищается для совместимости протоколов.
Файл .env
Пример ручной настройки:
AGENT_PROVIDER=openrouter
OPENROUTER_API_KEY=your-key
AGENT_MODEL=openrouter/free
OPENROUTER_BASE_URL=https://openrouter.ai/api/v1
AGENT_VISION=true
AGENT_MAX_TOKENS=4096
AGENT_TIMEOUT=90
- AGENT_PROVIDER — имя подключения, не URL.
- AGENT_VISION=false — режим текста и DOM без автоматических скриншотов.
- AGENT_MAX_TOKENS — лимит выходных токенов одного ответа, допустимо 256–32768.
- AGENT_TIMEOUT — таймаут одного HTTP-запроса, 5–300 секунд; это не лимит всей задачи.
.env загружается из корня проекта и имеет приоритет над одноимёнными переменными окружения. После изменения файла используйте /reload; после изменения Python-кода нужен перезапуск.

Отчёты и видео
После задачи программа выводит путь к результатам.
Путь	Что хранится
runs/<сессия>/task-001/result.json	Статус, итог, свидетельства и учёт токенов
runs/<сессия>/task-001/events.jsonl	Шаги, вызовы инструментов и ошибки
runs/<сессия>/video/	Видео при запуске с --record


Следующие задачи получают папки task-002, task-003 и т. д. Видео относится ко всей сессии и финализируется при закрытии браузера. Бинарные скриншоты в JSON-журнал не записываются.
Статус	Значение
completed	Агент сообщил о завершении после проверки результата
answered	Ответ в чате без заявления о выполнении браузерной задачи
partial	Работа не завершена, например исчерпан лимит шагов
blocked	Ошибка или ограничение не позволили продолжить


Архитектура
Наблюдение → решение модели → инструмент → Playwright → новое наблюдение. Перед завершением браузерной задачи требуется verify и описание свидетельств.
Модель использует простые команды вроде click_element и type_text. Версии наблюдений контролирует исполнитель. Проверка цели учитывает конкретный узел, его состояние и локальный контекст; постороннее изменение часов на странице не должно блокировать ввод. Скрипты и стили сайта при чтении не удаляются.
Для ограничения контекста сохраняется максимум один актуальный скриншот, а длинная история сокращается сводкой. После пяти ошибок без успешного действия цикл останавливается.
Модуль	Ответственность
agent/cli.py, agent/chat.py	Запуск, настройки и диалог
agent/runner.py	Цикл выполнения, восстановление и отчёты
agent/browser.py	Playwright и проверка цели
agent/context.py	Представление страницы и изменений
agent/model.py	Адаптеры API и диагностика ошибок
agent/tools.py	Схемы инструментов
agent/openrouter.py, agent/doctor.py	Настройка OpenRouter и проверка подключения
demo/, tests/	Демо-сайт и автоматические проверки


Проверки и ограничения
Для версии 0.9.1 пройден 61 автоматический тест, включая проверки реального Chromium. Интеграционный тест создаёт три задачи и завершает одну при обновлении отдельного счётчика страницы каждые 10 мс. В автоматическом тесте ответы модели заданы программно.
Отдельно выполнен пользовательский прогон через OpenRouter: агент сообщил completed и подтвердил три задачи с одной завершённой через DOM и скриншот. Сценарий работы с реальной почтой не подтверждён.
Запуск тестов — без реального API-ключа, с установленным Chromium:
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
Проект остаётся прототипом:
- Надёжность зависит от модели, кода исполнителя, сайта и доступности API. Бесплатные маршруты могут ограничивать запросы между успешными шагами.
- Сложные SPA и canvas не гарантированно поддерживаются; координатных кликов нет.
- DOM и скриншот не атомарны. Значимое изменение вне локального контекста цели может остаться незамеченным.
- CAPTCHA, 2FA и вход в аккаунт выполняются пользователем.
- completed — отчёт агента, а не независимое доказательство. Важные результаты проверяйте самостоятельно.
Решение проблем
Ошибка	Что делать
No module named playwright	Установите requirements.txt через Python из .venv и запускайте тем же интерпретатором
Не найден requirements.txt	Перейдите в корень проекта
Не установлен Chromium	Выполните .\.venv\Scripts\python.exe -m playwright install chromium
ERR_CONNECTION_REFUSED для порта 8765	Запустите демо-сервер в отдельном терминале
Не задан ключ или модель	Выполните --setup, затем --check
HTTP 400	Прочитайте Detail и error_type: возможна несовместимость параметров, истории или изображений. Причину нельзя определить по одному коду
HTTP 401 / 403	Проверьте ключ, доступ и подробности ответа сервиса
HTTP 402	Проверьте баланс и ограничения расходов
HTTP 404	Проверьте точный ID модели и доступность её маршрута
HTTP 429	Учитывайте квоты и время ожидания сервиса. Частые /retry не восстанавливают квоту
Повторяющийся Stale DOM	Проверьте версию, сохраните журнал: цель или её контекст изменяются между осмотром и действием


При обновлении остановите процесс и замените всю папку agent, сохранив свои .env, .venv и .profile. /reload обновляет настройки, но не Python-код.
После сбоя сначала проверьте фактическое состояние сайта: часть действий могла выполниться. /retry просит модель учесть это, но не гарантирует отсутствие повторов.
Приватность и публикация
Текст страниц и скриншоты передаются выбранному API. Журналы и видео могут содержать письма, введённый текст и другие личные данные.
Не публикуйте:
- .env — API-ключи;
- .profile/ — cookies и сессии аккаунтов;
- .venv/ — локальное окружение;
- runs/ — непроверенные журналы и видео.
Используйте .env.example с фиктивными значениями. Добавьте исключения в .gitignore и проверьте состав коммита:
git status
git diff --cached --name-only
.gitignore не убирает уже отслеживаемые файлы. Если ключ был опубликован, отзовите его — удаления файла из последнего коммита недостаточно. Пароли вводите вручную; ограничения на оплату и удаление в инструкциях модели не заменяют техническую систему разрешений.
